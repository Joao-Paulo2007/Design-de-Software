# Matriz de trade-offs

| Estilo | Vantagens | Desvantagens | Decisão para o semestre |
|---|---|---|---|
| Monólito simples | Fácil de executar e ensinar | Pode acoplar responsabilidades | Não escolhido como forma final |
| Camadas/modular | Organização clara, baixo custo didático | Pode virar camadas anêmicas | **Escolhido** |
| Microsserviços | Escalabilidade independente | Complexidade operacional alta | Não necessário neste projeto didático |
| Eventos | Bom desacoplamento temporal | Observabilidade e consistência mais difíceis | Usado pontualmente para notificações |

## Decisão
Adotar monólito modular em camadas para manter o foco em Design de Software, sem sobrecarregar os alunos com infraestrutura.
